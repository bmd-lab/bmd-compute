## Recovery

The first two staging requests reached finalization on POWER and failed in
Paramiko's `stdout.read()` with `TimeoutError` after the runner's default
60 s command timeout: finalization prints its result only when it has
finished. Each request ended with HTTP 503 (`staging_unavailable`), left the
attempt `STAGING` locally and remotely, and released its claim.

The correction `b13f01f` gives finalization (staging and re-verification)
its own 300 s timeout; every other remote command keeps 60 s. The third
request, for the same attempt and validation root, resumed in the same run
directory: the inventory found every uploaded file complete with the
expected hashes, so no scientific input was uploaded again, and staging
completed.

POTCAR identity checks parse each POTCAR with pymatgen; finalization checks
the library file, the staged copy and, again, the staged copy during the
staged-input verification, so the identity time includes calls made inside
the verification. The cost grows with the number of elements: a ternary
search would need about three times the identity time, which remains within
300 s on this evidence but with a smaller margin.
